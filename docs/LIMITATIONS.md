# Release 0.1.0 preview limitations

- A scan reads metadata as an ordinary user. Windows and Linux still send these requests through the OS filesystem stack. The cause of a system stop requires separate diagnosis.
- The scope is one local root and its mount or volume. Junctions, symlinks, managed cloud placeholders and unsupported special filesystem entries are excluded. Windows verifies directory identity around enumeration and uses no-reparse flags for each opened leaf. Concurrent replacement of an ancestor can still race those Win32 path operations. Linux WSL 1 uses the weaker mountinfo plus device fallback. A native Linux kernel remains to be tested.
- Totals cover regular files and default data streams. They exclude directories' own blocks, filesystem metadata, alternate streams and shared extent accounting. An unknown measurement has a separate quality. Scan-time identity conflicts can produce an unknown hardlink contribution. Aggregation uses stored observations, including during recovery and after cancellation.
- Partial results are available once rows are committed. A canceled collection can leave totals unaggregated. **부분 결과 집계** computes totals from the stored rows after the worker exits. A worker still blocked in a filesystem call remains in the cancellation-waiting state.
- The cache budget and free-space reserve apply to the active private scan directory. SQLite temporary files outside that directory, old session directories, and imported copies use additional space. The chosen cache base is excluded from the current scan. Old cache locations from before a settings change require an explicit exclusion. Recovery discovers the cache after worker loss while the app is open. Automatic discovery and archival across app restarts are pending. Keep a `.dscan` for results you want to reopen.
- GUI comparison shows counts and up to 250 paths. The CLI can export the full comparison. CSV/JSON/JSONL export covers the whole result. Filtered selection export, live OS capacity cards and a diagnostic export UI are pending. The worker writes one small path-free terminal summary per scan.
- GTK background query pages are bounded. The resident page budget estimates retained model data; GTK-held references and pending query pages use separate memory. Expanding large numbers of folders, collating search paths, and sorting very wide folders can take longer. While scanning, the expanded tree stays in place; use **결과 새로고침** for a fresh view. Treemap clicks select items in the first 512 rows of the current list when available. Other clicks show the path in the detail panel.
- Windows clean VM, cloud provider hydration, ReFS/exFAT, native Linux invalid-byte filename behavior, Wayland and the desktop scaling matrix remain unverified. See [Validation](VALIDATION.md) for environments and results.

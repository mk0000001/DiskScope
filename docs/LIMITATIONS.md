# Release 0.1.3 preview limitations

- A scan reads metadata as an ordinary user. Windows and Linux still send these requests through the OS filesystem stack. The cause of a system stop requires separate diagnosis.
- The scope is one local root and its mount or volume. Junctions, symlinks, managed cloud placeholders and unsupported special filesystem entries are excluded. Windows verifies directory identity around enumeration and uses no-reparse flags for each opened leaf. Concurrent replacement of an ancestor can still race those Win32 path operations. Linux WSL 1 uses the weaker mountinfo plus device fallback. A native Linux kernel remains to be tested.
- Totals cover regular files and default data streams. They exclude directories' own blocks, filesystem metadata, alternate streams and shared extent accounting. An unknown measurement has a separate quality. Scan-time identity conflicts can produce an unknown hardlink contribution. Aggregation uses stored observations, including during recovery and after cancellation.
- Partial results are available once rows are committed. A canceled collection can leave totals unaggregated. **부분 결과 집계** computes totals from the stored rows after the worker exits. A worker still blocked in a filesystem call remains in the cancellation-waiting state.
- The active scan budget covers its private scan directory. Temporary files outside that directory and imported copies use additional space. Retention applies to idle, verified DiskScope cache directories in the configured base. Live, displayed, legacy, unreadable and unrecognized directories are skipped. A pass makes no deletions if it finds more than 4,096 eligible directories, or if it cannot verify the configured path. The protected recovery can exceed the retention thresholds by itself. Save a standalone `.dscan` outside the private directories for durable archives. The scanner excludes the configured base. Old cache locations require an explicit exclusion.
- GUI comparison shows counts and up to 250 paths. The CLI can export the full comparison. A filtered export can include matches beyond the displayed page or the Top 100/1000 cap. An empty CSV contains column headers. The volume card displays the reading captured at scan start. The worker writes one small path-free terminal summary per scan. The diagnostic report reads committed results and can include the displayed scan root by explicit selection. Filesystem type and driver details are outside the report.
- New scans save SQLite schema version 2 for volume information. The current app opens both v1 and v2 snapshots. The 0.1.0 application accepts v1 snapshots. JSON and JSONL retain wire schema version 1.
- GTK background query pages are bounded. The resident page budget estimates retained model data. GTK-held references and pending query pages use separate memory. During a scan, the unfiltered tree shows committed observations in discovery order and refreshes expanded folders. Folder totals and hardlink deduplication are pending until aggregation. The treemap preview uses up to the first 512 observed children of the selected folder. At worker exit the results view reloads in size order. Treemap clicks select items in the first 512 rows when available. Other clicks show the path in the detail panel.
- Windows clean VM, cloud provider hydration, ReFS/exFAT and full desktop scaling remain unverified. See [Validation](VALIDATION.md) for measured desktop latency and the environments exercised.
- On WSL 1, SQLite read transactions sometimes wait on the active worker's WAL. The tree may show its latest readable commit late. Opening the finished result remains supported.
